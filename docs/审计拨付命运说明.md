# 审计拨付命运说明（FATE-AUDIT-RELEASE-01）

- 产品：保证金笼（本仓 `data/app.db`，SQLite 本机文件库，不换库不换入口会话）
- 锁定日期：2026-11-22（当日锁定，之后只准按本说明执行，禁止增补第三路）
- 适用动作：解笼拨付 `POST /api/releases`（action=`cage_release`）
- 关联模块：解笼服务 `release_svc`、审计服务 `audit_svc`、对账服务 `reconcile_svc`、入笼服务 `cages_svc`

## 一、选定路径：甲路径（亮成功审计则拨付册必有对应行，否则审计零改）

本仓**只走甲路径一种口径**，全链路不得与乙路径混用。

甲路径成败边界（同一 SQLite 事务、同一 `conn.commit()`）：

1. 先取得笼锁 `cage:{cage_id}`，未取得锁者不进入本边界（见第二节争用规则）。
2. 业务校验（笼存在、状态为核验通过/部分解笼、核验结论与笼代对齐、金额合法）。
3. **先**向拨付册 `releases` 插入真实行并拿到 `release_id`，凭证号 `release_ref` 必须在册内唯一可查。
4. 同事务更新笼面 `cages.available/status` 与保证金户 `bond_accounts.frozen/balance`。
5. 审计服务以**守卫方式**写成功审计 `cage_release`：写入前回查同一事务内的拨付册行，
   凭证号与金额必须对得上；对不上即判定审计拨付偏航，拒绝写成功审计并抛出
   `AuditReleaseYaw`，解笼服务先整笔回滚业务事务
   （笼面、账户、拨付册、成功审计全部零改）。
6. 以上 3–5 步全部成功才允许 `commit()`；业务异常一律 `rollback()`，
   成功审计零增、拨付册零增、笼面零改。

因此终态恒等式成立：

> 每一条 `cage_release` 成功审计 ⇔ 恰好一行同凭证号、同金额、同笼代的 `releases` 已拨付行。

反向同样成立：拨付册新增一行已拨付行，必有同凭证号的成功审计；不允许“有行无审计”。

### 禁止事项

- 禁止诱惑第三路（影子拨付、先审计后补行、异步补录、内存态假成功等一律禁止）。
- 禁止甲乙混用：不得出现“拨付未落但成功审计照写、只留未完成痕”的乙路径写法。
  混用必然复现“有审计无拨付”，按偏航处理。
- 禁止只改审计页文案掩盖分裂；页面只允许展示真实册行与守卫结果。
- 对账服务禁止再用笼面缺口反推出金；`released` 只准取 `releases` 册内 `SUM(amount)`，
  册里没有就是 0，缺口如实暴露为 `balanced=false`。

### 偏航记录与拒写

- 守卫函数位于审计服务 `audit_svc.write_release_audit_guarded()`：
  回查不到拨付册行或凭证/金额/笼代/状态不一致时，**不在业务事务内写痕**
  （SQLite 单写者，事务未提交时独立连接无法写入；同事务写痕又会被业务回滚撤掉），
  只携带原因与凭证号抛出 `AuditReleaseYaw`。
- 解笼服务捕获后先 `rollback()` 业务事务（册行/笼面/账户/成功审计零改），
  再调 `audit_svc.record_release_yaw()` 用**独立连接**落一条
  `action=audit_release_yaw` 偏航痕（payload 含原因与凭证号），与业务成败边界隔离。
- 偏航痕是告警不是成功审计：`cage_release` 成功审计在该次请求中保持零增。
- 验收时凡出现“成功审计无对应拨付行”一律记为审计拨付偏航并拒写、拒收。

## 二、锁争用规则（独立验收段，与第一节命运口径分开验收）

- 双柜员同时解同一笼，按 `cage_locks` 抢锁排队：先到者持锁完成事务，
  后到者 `try_acquire` 失败，只向 `contention_log` 留痕（action=争用），
  返回 409，不写任何业务数据（笼面、拨付册、账户、成功审计均零改）。
- 持锁者在 `finally` 中释放笼锁；异常回滚后锁仍须释放，避免死锁。
- 争用留痕与命运说明分别在不同验收段检验：争用段只看锁/争用表，
  命运段只看审计与拨付册的一一对应。

## 三、五页凭证对齐口径

解笼链路五个页面（保证金户、入笼冻结、解笼拨付、对账互证、审计争用）展示的
出金凭证必须同源同值：凭证号一律来自 `releases.release_ref` 真实行，
审计页 `cage_release` 载荷内的 `release_id` 必须非空且能在拨付册按凭证号查到同行；
对账页“拨付”列只汇总册内行，不得反推。
